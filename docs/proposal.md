# VibeShield — предложение по продукту

> Рабочее название: **VibeShield** (свободны также `easyvibegate`, `safevibe`, `vibescan`).
> Заняты: `vibe-audit`, `vibecheck`, `vibeguard`, `vibesecurity`.

Open-source сканер безопасности для «вайб-кодинговых» проектов. Одна команда, любой стек,
понятный отчёт с готовыми фиксами. Главное отличие от аналогов — не просто грепает утёкшие
ключи, а **реально доказывает дыры в доступе к данным** (RLS, IDOR, анонимный доступ к БД) —
именно то, чем ломают приложения «через F12».

---

## 1. Что делает референс `vibe-audit` и где его потолок

- **Стек:** чистый Python, без зависимостей, ~450 строк. Сканирование — regex по тексту файлов.
- **Проверяет (13 категорий):** хардкод-ключи (OpenAI/AWS/Stripe/Supabase service_role и т.д.),
  `.env` в git, ключи во фронте, `NEXT_PUBLIC_`/`VITE_` секреты, CORS `*`, `debug=True`, `eval()`,
  SQL f-strings, JWT `alg:none`, `npm audit`, отсутствие rate-limit, незащищённые LLM-эндпоинты,
  клиентские роли/IDOR-эвристики, docker-compose с дефолтными паролями.
- **`livecheck.py`:** пассивно дёргает задеплоенный сайт — ищет открытые `.env`, `.git/config`,
  `backup.sql`, проверяет security-заголовки и флаги cookie.
- **Честный дисклеймер в README:** «это линтер типовых ошибок, а не пентест». Прямо признаёт, что
  **не проверяет**: логику авторизации, права в облачной консоли, RLS-политики Supabase, инфраструктуру.

**Вывод:** инструмент ловит «мусор на поверхности» (ключи и конфиги), но пропускает ровно то,
что реально приводит к взломам. И работает только на regex — много ложных срабатываний, легко обойти.

## 2. Что на самом деле ломают в вайб-кодинговых приложениях

Данные из свежих аудитов и разборов (2025–2026):

- **65%** просканированных приложений имели проблемы, **58%** — хотя бы одну критическую.
- **88%** вайб-кодинговых приложений на Supabase имели **полностью выключенный RLS** — БД отдавала
  любую строку любому запросу с anon-ключом.
- **CVE-2025-48757**: 170+ приложений на Lovable с неаутентифицированным доступом к данным — ИИ
  просто не добавил проверку доступа в сгенерированные API-роуты.
- Утёкшие `service_role` ключи и Supabase-креды прямо в коде фронта — массово.

Семь типовых классов дыр: **утёкшие секреты, сломанная аутентификация, IDOR/BOLA (доступ к чужим
данным), инъекции, prompt injection, подробные ошибки, устаревшие зависимости.**

**Сценарий «подделать через F12», о котором ты говорил** — это как раз IDOR + отсутствие RLS +
доверие к клиенту: браузер меняет `user_id`/`role`/URL в запросе, а сервер (или БД) это не проверяет.
**Ни один бесплатный сканер это уверенно не ловит** — потому что это видно только в рантайме,
а не в тексте кода.

## 3. Рынок: кто уже есть и чего всем не хватает

| Инструмент | Тип | OSS | Что делает | Слепая зона |
|---|---|---|---|---|
| vibe-audit | CLI/skill | ✅ | regex по коду + лёгкий live-чек | RLS, авторизация, IDOR |
| Semgrep CE | SAST | ✅ | паттерны в коде | межфайловый data-flow, бизнес-логика |
| Gitleaks / TruffleHog | secrets | ✅ | утёкшие ключи | всё, кроме секретов |
| Trivy / osv-scanner | deps | ✅ | уязвимые пакеты | достижимость уязвимости |
| OWASP ZAP / Nuclei | DAST | ✅ | скан живого сайта | только найденные роуты |
| supabomb / supabase-security-skill | probe | ✅ | активный anon-пробинг Supabase | только Supabase |
| firepwn / OpenFirebase / firescan | probe | ✅ | пробинг Firebase | только Firebase |
| VibeCheck / Vibe App Scanner / Aikido | web/платформа | ❌ | коммерческие, closed | — |

**Ключевой вывод рынка (сходятся все обзоры):** инструменты живут в трёх изолированных силосах —
секреты / статический анализ кода / динамический пробинг. **Никто не связывает их в один поток и
не доводит до главного — доказательства, что дыра реально стреляет.** Статики недостаточно:
«политика существует» ≠ «политика сравнивает правильного пользователя».

Вот эта незанятая ниша — **«один инструмент, который и находит, и подтверждает access-control дыры
на любом стеке»** — и есть место для нашего продукта.

## 4. Концепция VibeShield

**Одна команда → автоопределение стека → слои проверок → отчёт с доказательствами и фиксами.**

Философия: не переизобретаем секрет-сканеры и SAST (обернём готовые), а вкладываемся в то, чего нет
ни у кого бесплатно — **активная проверка доступа к данным**.

### Архитектура: модульные «чекеры»

**Layer 0 — Recon / детект стека.** Читаем `package.json`, `requirements.txt`, лок-файлы, конфиги
фреймворков. Определяем: фронт (Next/Vite/React/Vue/Svelte), бэкенд (Supabase/Firebase/собственный API),
задеплоенный URL (если дан). От этого зависит, какие модули включатся.

**Layer 1 — Статика (стек-агностик).**
- Секреты — обёртка над `gitleaks` (entropy + broad ruleset), не свои regex.
- Экспозиция во фронте: `service_role` в клиенте, `NEXT_PUBLIC_`/`VITE_`/`REACT_APP_` с секретами.
- Конфиги: CORS `*`, debug, `eval`, конкатенация SQL, JWT `alg:none`, **отсутствие проверки подписи
  Stripe-webhook**, открытые Firebase-правила `if true`, **`CREATE TABLE` без `ENABLE ROW LEVEL SECURITY`**
  в SQL-миграциях.
- `.env` в git, отсутствие в `.gitignore`.
- Зависимости: обёртка над `npm audit` / `osv-scanner`.
- (Опц.) Semgrep с кураторским набором правил под authz: клиентская роль, роут/Server Action без auth.

**Layer 2 — Активный пробинг бэкенда (главное отличие).** Целимся в Supabase + Firebase — на них
построено подавляющее большинство вайб-приложений.
- **Supabase:** по URL + anon-ключу (находим в бандле или берём из флага) дёргаем `/rest/v1/` OpenAPI →
  перечисляем таблицы → пробуем анонимный `SELECT` по каждой → список таблиц, читаемых анонимом
  (RLS выключен/дырявый). Пробуем анонимные `INSERT/UPDATE/DELETE` по canary-строке → таблицы,
  доступные на запись. Перечисляем `/rest/v1/rpc` и `/storage/v1/bucket` → публичные бакеты и RPC.
- **Firebase:** по конфигу пробим Firestore/RTDB/Storage REST-эндпоинты анонимно на чтение/запись.
- **Именно этот слой ловит «88% с выключенным RLS» и сценарий «форжу через F12»** — потому что
  доказывает: анонимный браузер реально читает/пишет твою БД. В отчёт кладём готовый `curl` как улику.

**Layer 3 — Живой сайт (универсально, любой стек).**
- Открытые файлы: `.env`, `.git/config`, `backup.sql`, `.DS_Store`, **source maps** (утечка исходников).
- Security-заголовки: CSP, HSTS, X-Frame-Options, X-Content-Type-Options.
- Флаги cookie, утечка `Server`/`X-Powered-By`, debug-страницы.

**Layer 4 — (продвинутый, roadmap) Дифф двух аккаунтов = IDOR/BOLA.**
Два тестовых пользователя (юзер даёт два токена или тул сам заводит двух throwaway-юзеров через
Supabase Auth), повторяем одни и те же запросы и **сравниваем ответы** — ловим доступ к чужим данным.
Это прямой ответ на страх «зайдут под чужим / подделают данные».

### Отчёт
Один Markdown + HTML + JSON. Каждый finding: **что / где** (`file:line` или endpoint) / **улика**
(отредактированная) / **почему это важно** одной строкой / **готовый фикс** (SQL для RLS, сниппет конфига).
Плюс: severity (🔴/🟡/🔵), **security score** и бейдж для README (социальное доказательство → звёзды),
exit-коды для CI, режим **`--ai-fix`** — выдаёт готовый промпт для вставки обратно в Cursor/Claude.

---

## 5. Почему обещание «любой стек» честно

- **Layer 1 (статика) и Layer 3 (live)** — полностью стек-агностик.
- **Layer 2 (пробинг)** целится в Supabase/Firebase — это ~весь рынок бэкендов вайб-кодеров.
  Для других бэкендов деградируем мягко: остаются статика + live.
- В README пишем это честно (в отличие от завышенных обещаний конкурентов) — доверие = звёзды.

## 6. Технологический выбор

**Рекомендую TypeScript / Node.** Причины:
- Приложения вайб-кодеров в основном на JS/TS — попадаем в их экосистему.
- `npx vibeshield .` — привычная им установка без трения.
- Легко упаковать в Claude Code / Cursor / Windsurf skill (`npx skills add ...`) — там они и живут.

Python (как у `vibe-audit`) — рабочая альтернатива (`uvx vibeshield`), но по аудитории TS выигрывает.

**Переиспользуем, а не пишем с нуля:** `gitleaks`, `osv-scanner`/`trivy`, опц. `semgrep` — дёргаем как
бинари. **Своими руками пишем только то, что даёт уникальную ценность:** Supabase/Firebase-пробер и
live-чекер. Это небольшой и очень «продаваемый» код.

## 7. Дистрибуция и рост (под звёзды)

- Установка в одну строку: `npx vibeshield .`
- **Skill для Claude Code / Cursor / Windsurf** — встречаем вайб-кодера в его инструменте.
- **GitHub Action** + комментарий в PR (score + топ-находки).
- **Бейдж и shareable-отчёт** → социальная петля (как у VibeCheck).
- README с «пугающей» статистикой (88% RLS off, CVE-2025-48757), demo-GIF, «скан за 30 секунд».
- Пост-разбор «я просканировал N приложений и нашёл X дыр» — заходит на DEV.to / Reddit.

---

## 8. Этика и безопасность (важно для активного пробинга)

- Сканируем **только свой** проект/URL. Перед активным пробингом живого домена — обязательный флаг
  подтверждения владения (`--i-own-this`).
- По умолчанию **read-only**. Write-пробы — только на canary-строках, с автоочисткой, строго opt-in.
- Rate-limit на запросы. Без брутфорса и фаззинга.
- Дисклеймер: «zero findings ≠ безопасно», это не замена пентесту.

## 9. MVP (v0.1, ~1–2 уикенда)

1. Каркас CLI + детект стека + рендер отчёта (MD/JSON, score, exit-коды).
2. Статика: секреты (обёртка `gitleaks`) + экспозиция во фронте + конфиги + **RLS-missing в миграциях** + `.env`/git.
3. **Supabase active anon-probe** (чтение/запись таблиц, бакеты, rpc) — киллер-фича.
4. Live: открытые файлы + заголовки.
5. Красивый отчёт + бейдж.

**Roadmap:** v0.2 — Firebase-пробер, GitHub Action, packaging в skill. v0.3 — дифф двух аккаунтов
(IDOR/BOLA), `--ai-fix`, Semgrep-набор правил под authz.

## 10. Одной фразой

> **vibe-audit** говорит «у тебя ключ в коде».
> **VibeShield** заходит anon-ключом в твою БД, выкачивает чужие данные и кладёт в отчёт `curl`,
> которым это повторить — с готовым SQL, чтобы починить.
