# VibeGate — согласованный технический спек (v0.3 дизайна)

Универсальный интерактивный сканер безопасности для вайб-кодинговых проектов.
Один движок проверок, две обёртки: skill (Cursor/Claude) и CLI-визард (терминал).
Пакет и бинарь: `vibegate` (свободно в npm).

> Переименован из VibeShield — то имя занято живым коммерческим продуктом vibe-shield.com.

## Главный принцип

**Ширина + честность про глубину.** Осмотр кода работает на любом стеке. Живая проверка тоже
универсальна, но делится на две части: что можно проверить детерминированно (без ИИ) — делаем сами;
что требует адаптивного поведения (логин, сбор ID, оценка ответов) — исполняет ИИ-агент через skill,
а в голом CLI это degrade в «ассист» (готовим запросы, подтверждает пользователь).

Инструмент сам определяет стек, объясняет, что умеет, и на каждом шаге спрашивает разрешение.

## Что автомат, а что ассист (ключевая таблица честности)

| Проверка | Стек | Режим |
|---|---|---|
| Осмотр кода (секреты, конфиги, RLS в миграциях) | любой | ✅ автомат |
| Список эндпоинтов из исходников | любой (Next/Express/Fastify/FastAPI/Django/Rails) | ✅ автомат |
| Анонимный пробинг эндпоинтов (отдаёт ли без входа) | любой + запущенное приложение | ✅ автомат |
| Supabase/Firebase anon-проб (таблицы, бакеты, rpc) | Supabase/Firebase | ✅ автомат, самый сильный |
| Дифф-харнесс IDOR (две сессии → крест-накрест) | любой, если даны 2 сессии | ✅ автомат по данным сессиям |
| Логин, сбор реальных ID, оценка спорных ответов | любой | 🤖 ИИ-агент (skill) / 👤 ассист (CLI) |

## Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Имя | **VibeGate** (`vibegate`, свободно в npm) |
| Стек инструмента | TypeScript / Node |
| Форма | Один движок + две обёртки: skill + CLI-визард |
| Репозиторий | Корень — папка `EasyVibe` |
| Фокус | Ширина: любой бэк (автомат где можно, ассист/ИИ где нельзя) |
| Модель работы | Интерактивная, по уровням, с согласием на каждом шаге |
| Ядро | Без обязательных внешних бинарей; тяжёлые инструменты — по запросу |
| Оценка | Gate (pass/fail по критическим) + балл 0–100 + бейдж |
| Активная запись (canary) | За отдельным подтверждением; `--read-only` для отката |
| Ложные срабатывания | `vibegate.config.json` + inline `// vibegate-ignore` |

## Три уровня (опросник)

### Уровень 0 — Осмотр кода. Мгновенно, ничего не ставим. Любой стек.
- **secrets** — хардкод-ключи (свой набор паттернов + entropy).
- **client-exposure** — секреты/`service_role` во фронте, `NEXT_PUBLIC_`/`VITE_`/`REACT_APP_`.
- **config-risks** — CORS `*`, debug, `eval`, конкатенация SQL, JWT `alg:none`, Stripe webhook без подписи.
- **rls-migrations** — `CREATE TABLE` без `ENABLE ROW LEVEL SECURITY`.
- **env-git** — `.env` в git, отсутствие в `.gitignore`.
- **route-inventory (advisory)** — вычитываем список эндпоинтов и помечаем те, где в коде не видно проверки
  доступа. ⚠️ Это ПОДСКАЗКА, не приговор: проверка часто в middleware/декораторе/DI. Не роняет gate,
  а формирует список целей для Уровня 2. (Так избегаем шума, из-за которого удаляют другие сканеры.)

### Уровень 1 — Глубокий анализ кода. Может понадобиться доставить инструменты.
Спрашивает «качаем X? да/нет». Отказ → пропуск + отметка.
- **deps** — уязвимые библиотеки (`npm audit` / `osv-scanner`).
- (Опц.) обогащение через `gitleaks` / `semgrep`, если пользователь их поставил.

### Уровень 2 — Живая проверка. Нужно согласие + запущенное приложение/URL.
- **2a. Пассивные (низкий риск, URL + подтверждение владения):** exposed-files, headers, анонимный
  endpoint-probe (read) по списку из Уровня 0.
- **2b. Активные (доп. подтверждение):**
  - **backend-probe** — Supabase/Firebase anon-ключом (read + write-canary с автоочисткой). Автомат.
  - **idor-harness** — дифф двух сессий по повторённым запросам. Автомат по данным сессиям; логин и
    сбор ID даёт ИИ-агент (skill) или пользователь (ассист).

## Раскладка репозитория

```
package.json            # bin: vibegate (CLI-визард)
tsconfig.json
src/
  engine/               # чистый детерминированный движок, без UI и без ИИ
    detect.ts
    config.ts
    report.ts           # Finding, score/gate, рендер md/json/html + бейдж
    types.ts
    checkers/
      static/           # secrets, client-exposure, config-risks, rls-migrations, env-git, route-inventory
      deep/             # deps (+ опц. gitleaks/semgrep)
      live/             # exposed-files, headers, endpoint-probe, idor-harness
      backend/          # supabase.ts (v0.1), firebase.ts (v0.2)
  orchestrator/         # логика уровней и согласий (общая для skill и CLI)
    flow.ts
    prompts.ts
  cli/index.ts          # терминал-визард; npx vibegate
  skill/SKILL.md        # обёртка для Cursor/Claude — ведёт диалог и даёт адаптивную часть Уровня 2
templates/report.html
tests/
README.md
```

## Модель находки

```ts
type Severity = 'critical' | 'warning' | 'info' | 'advisory';
interface Finding {
  id: string;
  severity: Severity;      // advisory не влияет на gate
  title: string;
  where: string;           // "src/app.ts:42" или "GET /api/orders/123"
  detail: string;
  evidence?: string;       // отредактированная улика (готовый curl)
  fix: string;
  checker: string;
  level: 0 | 1 | 2;
}
```

## Оценка

- **Gate:** `fail` при любой `critical`, иначе `pass`. `advisory` не учитывается.
- **Балл:** старт 100; critical −25, warning −8, info −2; пол = 0.
- **Бейдж:** цвет по gate/баллу; Markdown-сниппет для README.
- **Exit-коды (`--ci`):** 0 чисто, 1 warning, 2 critical.

## Безопасность и этика

- Уровни 0–1 — только чтение файлов, безопасно.
- Уровень 2 — только по подтверждению владения (вопрос или `--i-own-this`).
- Запись (canary) — отдельное подтверждение, помеченные строки, автоудаление; `--read-only` отключает.
- Rate-limit, без брутфорса/фаззинга. Дисклеймер: «zero findings ≠ безопасно».

## Позиционирование (чтобы собрать звёзды)

Рынок уже плотный (vibe-audit, vibeship-scanner 127★, VibePenTester 177★, VibeSecurity, vibesafe и др.).
Ещё один набор commodity-проверок звёзд не даст. Единственное отличие VibeGate — **доказательство, что
дыра стреляет:** не «возможно RLS выключен», а «вот `curl`, которым аноним читает таблицу users, и вот
SQL, чтобы закрыть». Это и есть крючок для README и постов.
