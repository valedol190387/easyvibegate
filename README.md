🇬🇧 English version: [README.en.md](README.en.md)

**Проверка безопасности для приложений, собранных «на вайбе». Находит частые дыры и показывает доказательства там, где может.**

Большинство сканеров просто грепают код и говорят «возможно, ты слил ключ». EasyVibeGate идёт дальше: для **Supabase/Firebase** заходит публичным ключом и показывает, какие таблицы читаются кем угодно, с готовым `curl` и SQL для починки. И он честен про покрытие: каждая проверка сообщает, реально ли она выполнилась, поэтому упавшая или пропущенная проверка **никогда не выдаётся за зелёное «всё чисто»**.

> Статус: **v0.4, ранняя версия.** Лучше всего поддержан стек **Next.js + Supabase**. Осмотр кода работает на любом стеке; живой пробинг бэкенда — только чтение и заточен под Supabase/Firebase. Это не пентест.

## 🇷🇺 Простыми словами

**Что это.** Проверка безопасности для приложений, собранных «на вайбе» с помощью ИИ (Cursor, Lovable, Bolt, Replit и т.п.). ИИ пишет код, который работает, но часто оставляет дыры: ключи прямо в коде, открытую всем базу данных, доступ к чужим данным. EasyVibeGate их находит и подсказывает, что чинить.

**Зачем.** Чтобы никто не скачал твою базу пользователей и не подделал данные через консоль браузера (F12).

**Как пользоваться — 3 шага:**
1. В папке своего проекта запусти одну команду (или попроси ИИ-агента — см. ниже).
2. Ответь на пару вопросов «да / нет».
3. Получишь понятный отчёт и готовый план починки — вставь его в свой ИИ (Cursor/Claude), и он всё исправит.

Разбираться в том, что внутри, не нужно: сложное — под капотом, снаружи одна команда и вопросы «да / нет».

## Как запустить

Три способа — выбери удобный.

### Способ 1. Через ИИ-агента (самый простой)

Если ты пользуешься **Cursor, Claude Code или Codex** — руками в терминал вводить ничего не надо. Открой проект в агенте и вставь ему такой промт:

```
Проверь безопасность этого проекта с помощью EasyVibeGate и объясни результат простыми словами.

1. Запусти в корне проекта:  npx easyvibegate . --no-wizard --deps
   (Добавь  --url <адрес-моего-приложения> --i-own-this  только если это мой проект
    и я разрешаю живую проверку бэкенда.)
2. Открой и изучи файл:  easyvibegate-report/ai-fix-prompt.md
3. Объясни простыми словами: что нашлось, насколько это опасно, самое срочное — первым.
4. Предложи конкретные исправления, но НЕ меняй код без моего подтверждения.
```

Агент сам всё запустит, прочитает отчёт и объяснит выводы. Можно так же просто сказать: «запусти EasyVibeGate и скажи, что не так».

### Способ 2. Одной командой в терминале

```bash
npx easyvibegate
```

Запусти внутри своего проекта. Дружелюбный мастер задаст пару вопросов «да/нет», понятным языком расскажет, что не так, и создаст готовый план починки. Ни установки, ни настройки, ни зависимостей.

### Способ 3. В CI (GitHub Actions)

Добавь `.github/workflows/easyvibegate.yml`:

```yaml
name: EasyVibeGate
on: [push, pull_request]
jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npx easyvibegate . --ci
```

Коды выхода: `2` — есть критичное, `1` — предупреждения, `3` — проверка не завершилась, `0` — чисто.

## Что делать с результатом

Открой `easyvibegate-report/ai-fix-prompt.md` и вставь его в свой ИИ-помощник (Cursor, Claude Code, Windsurf). Для починки безопасности бери **сильную модель — Claude Fable или Opus**, а не маленькую «быструю»: иначе что-то пропустит. Любой утёкший ключ — сразу меняй (rotate).

## Что проверяет

### Уровень 0 — осмотр кода (любой стек, только чтение, без установки)
- **Секреты в коде** — ключи OpenAI / Anthropic / AWS / Stripe / GitHub / Google, приватные ключи, `service_role` и секретные ключи Supabase.
- **Секреты во фронте** — настоящие секреты за префиксами `NEXT_PUBLIC_` / `VITE_` / `REACT_APP_`.
- **Опасные конфиги** — открытый CORS, включённый debug, `eval`, сборка SQL строками, JWT `alg:none`.
- **Таблицы без RLS** — миграции создают таблицы, но не включают `ENABLE ROW LEVEL SECURITY` (анализ по каждой таблице).
- **Гигиена .env / git** — через настоящую семантику git: закоммиченный `.env` — критично.
- **Инвентарь эндпоинтов** — список маршрутов как цели для живой проверки (без ложных обвинений).

### Уровень 1 — зависимости
Аудит пакетов через npm / pnpm / yarn. Ошибка реестра честно помечается как «не удалось», а не «чисто».

### Уровень 2 — живой пробинг (только чтение, только твои приложения, с подтверждением)
- **Supabase / Firebase** — заходим публичным ключом и показываем, какие таблицы/бакеты читаются кем угодно, с воспроизводящим `curl`. Таблицы с «чувствительными» именами (users, payments…) — критично; публичный контент — «подтверди намеренность».
- **Любой бэкенд, best-effort** — дёргаем найденные эндпоинты без входа; с двумя тест-аккаунтами (`--idor-tokens a,b`) сравниваем ответы на предмет доступа к чужому (IDOR). Это подсказки для проверки, а не доказательство; инструмент никогда не пишет.

## Оценка и статусы

- **Итог — одна политика для всего** (CI, JSON, бейдж, консоль): `fail` — есть критичное; `incomplete` — критичного нет, но какая-то проверка упала / выполнилась частично / не поддержана; `pass` — всё проверено и чисто.
- **Балл:** 0–100. При `incomplete` бейдж **никогда не зелёный**.
- **Покрытие:** строка «Проверки: N выполнено · M с ошибкой · K пропущено».
- **Коды выхода (всегда, не только с `--ci`):** `2` критичное, `1` предупреждения, `3` проверка не завершилась, `0` чисто.
- Отчёт записывает проверенный путь, версию и время, поэтому отчёты разных проектов не путаются.

## Подавление ложных срабатываний

Файл `easyvibegate.config.json`:

```json
{
  "ignore": ["generic_secret:src/fixtures/sample.ts"],
  "ignorePaths": ["tests/", "docs/"]
}
```

Или прямо в строке (на самой строке или над ней): `// easyvibegate-ignore`.

## Как запустить как skill (Cursor / Claude Code / Windsurf)

Файл `skills/easyvibegate/SKILL.md` делает EasyVibeGate навыком для ИИ-агента. Скопируй папку в каталог навыков агента, например: `cp -r skills/easyvibegate ~/.claude/skills/easyvibegate`.

## Честные ограничения

EasyVibeGate — **линтер частых дыр вайб-кодинга, а не пентест.** Ноль находок не значит «безопасно». Статический слой не знает, проверяет ли эндпоинт доступ — это может подтвердить только живая проверка на запущенном приложении, которым ты владеешь. Никогда не направляй живую проверку на чужие системы.

SQL не «ищется регулярками», а разбирается лексером: строки, комментарии и имена в кавычках — это отдельные токены, поэтому ключевое слово внутри строки или имени столбца не может быть принято за команду. Что анализатор знает про себя:

- **Порядок миграций внутри одной папки — настоящий**, и `DISABLE ROW LEVEL SECURITY` в более поздней миграции даёт критичную находку. **Порядок между разными папками — догадка**: если противоречащие друг другу команды лежат в разных каталогах, находка выдаётся как предупреждение «порядок неясен» — независимо от того, какая папка оказалась последней при сортировке.
- **DDL внутри `DO $$ … $$` считается выполненным**, если он безусловный. Любая команда под `IF … THEN` (`ENABLE`, `DISABLE`, `CREATE`, `DROP`) даёт предупреждение «состояние RLS не подтверждено»: выполнится ли ветка, статически не узнать, и утверждать обратное — в любую сторону — значит врать. Вложенные `IF` учитываются, `-- end if` в комментарии условие не закрывает. Если у тебя идемпотентная обёртка `IF NOT EXISTS`, проверь состояние в базе и при желании подави находку через `easyvibegate.config.json`.

## Язык

Интерфейс по умолчанию **русский**; английский — флагом `--lang en`. Сами находки остаются на техническом английском, чтобы их удобно было передать ИИ-агенту.

## Участие

Issues и PR приветствуются. Сборка: `pnpm install && pnpm build`; точка входа CLI — `dist/cli/index.js`; тесты — `pnpm test`. Новые проверки лежат в `src/engine/checkers/`, строки интерфейса — в `src/engine/i18n.ts`.
